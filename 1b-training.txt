Yep, Dude—and with only six records, that result is actually quite plausible.

The key is that your timer is measuring the whole journey, not just XML parsing versus JSON parsing. Your XML page uses the signed-in Quickbase session directly against the table endpoint. The REST page has an extra network/authentication operation before it can even query the records:

XML
Code Page
→ POST /db/{tableDbid}
→ XML response
→ parse
→ render

versus:

REST
Code Page
→ GET /v1/auth/temporary/{tableDbid}
→ receive temporary token
→ POST /v1/records/query
→ JSON response
→ parse
→ render

So REST is doing two HTTP requests, while your XML example is doing one. That can easily make REST appear twice as slow on a tiny dataset. Quickbase's Application Analyzer makes the same distinction: it obtains temporary authorization before making REST calls, and for long operations it caches those tokens and refreshes them periodically rather than acquiring a new one before every individual request.

That also means we should be careful about concluding:

“XML is twice as fast as REST.”

What we've actually demonstrated so far is:

For this browser Code Page, querying six records with a newly acquired temporary token on every load takes substantially longer end-to-end than the legacy XML API using the existing Quickbase session directly.

That's a much more accurate result.

we might discover something like:

At that point we'd know where the difference actually lives.

My suspicion is that the temporary-token request is responsible for a large proportion of what you're seeing—not JSON itself. JSON parsing six records is practically microscopic computational work.

And this is precisely why the Analyzer's architecture suddenly makes more sense: it doesn't request a fresh token before every REST operation. It gets one, stores the authorization header, makes many REST calls with it, and renews the token before its five-minute lifetime expires.

So I'd absolutely keep your current benchmark result in the lesson notes. It's a legitimate observation. Then let's dissect the timing before we decide what it means.
